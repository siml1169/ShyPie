# pii-core detector catalogue — evidence, checksums, false positives, scope

**Notation.** `<repo>` = this repository's checkout root; `packages/…` paths are relative to it, and
paths written `test/…` are relative to the package directory (`packages/pii-core/`).

Source of truth: [the interface reference](../interface-contract.md); implementation in `packages/pii-core/`.
Implementation: `<repo>/packages/pii-core/index.js` (JSON-exported table below is
generated by hand from the code; every row is covered by `test/detectors.test.js`).

**Method and evidence policy.** The detection rules below are the rules actually executed by the
package. Checksums are computed in local code and cross-checked two ways:

1. every checksummed fixture is *generated* programmatically (`test/helpers/fixtures.mjs`), so a
   positive test can only pass when the verifier and the generator agree on the algorithm;
2. the ISO 7064 MOD 11,10 implementation is additionally cross-checked against a **published
   example** recomputed by hand: German USt-IdNr `DE136695976` (public documentation example of the
   BMF check-digit procedure, not customer data). Trace: payload `13669597` → products
   `2, 10, 1, 3, 4, 7, 1, 5` → check `11 − 5 = 6` = 9th digit ✓.
3. SHA-256/HMAC are cross-checked byte-for-byte against `node:crypto` in `test/crypto.test.js`.

Standards are cited by identifier + publisher. The research environment had **no web access**
(`web_search`/`web_fetch` were unavailable), so URLs are cited only where the
canonical path is stable; anything not verified during this research is marked **UNVERIFIED**.

**Fixture policy (I9).** No fixture is read from disk and no user document is touched. Values are
produced by a deterministic LCG at test time; names/addresses use the official German
"Muster…" style; emails use the reserved `.invalid` TLD; no fixture value is printed in this note
or in test output. IBANs/cards/VAT-IDs/IdNrs are generated with random payloads and computed check
digits, so they are synthetic by construction (a collision with a live identifier is improbable and
never asserted).

## Placeholder derivation (I7)

`{{KIND_XXXXXXXX}}`, `XXXXXXXX` = first 5 bytes of `HMAC-SHA256(key, KIND + "\0" + value)` encoded as
RFC 4648 **Base32** (alphabet `A–Z2–7`, no padding, 8 chars = 40 bits), then uppercase. This is a
keyed MAC, not a bare hash: without the session key the token leaks nothing about the value, and the
same key+value always yields the same token (prompt-cache stability). Verified byte-for-byte against
`node:crypto` `createHmac` in `test/crypto.test.js`.

SHA-256 / HMAC primitives: FIPS 180-4 — <https://csrc.nist.gov/pubs/fips/180-4/upd1/final>;
FIPS 198-1 (HMAC) — <https://csrc.nist.gov/pubs/fips/198-1/final>; Base32 — RFC 4648 §6.

## Overlap resolution / priority

Detectors run independently; candidates are resolved non-overlapping by
priority → length → start offset:

`SECRET(100) > BLOB(95) > IBAN(90) > CARD(85) > VATID(82) > TAXID(80) > IDNR(78) > EMAIL(72) >
BIC(70) > SSN(65) > PASSPORT/IDCARD(60) > PHONE(55) > ADDRESS(50) > ACCOUNT(45) > DOB(40) > PERSON(20)`

Consequences: an email inside a BIC-shaped uppercase domain is masked as one `EMAIL` span (not split
by `BIC`); `user:pass@host` is one `SECRET` span; a `PERSON` allow-word inside any other hit never
splits it. Placeholder spans in the input (strict or model-rewritten) are excluded from all
detectors, which is what makes `redact(redact(x)) === redact(x)` hold (I6).

Test command (per directory, bundled Node v24.21.0):
`node --test test/` → **50 tests, 49 pass, 0 fail, 1 skipped** (the 0600-mode assertion is skipped on
Windows, which does not model POSIX modes; the key file is still written with `mode: 0o600` and

six `*.test.js` files). `node --test` (auto-discovery) and
`node --test "test/**/*.test.js"` also work.

Coverage map: every row above appears in `test/detectors.test.js` as a positive case and the
contract's negative list (UUID, semver, ISO date, IP, order id, hex hash, short base64, `1.2.3`) plus
checksum-failure cases (broken mod-97 IBAN, broken Luhn card, broken MOD 11,10 VAT-ID/IdNr) are
asserted to produce **zero** hits. `test/redactor.test.js` asserts no plaintext on any output
surface (`text`, `tokens`, `hits`, `stats`, error messages), determinism, idempotency and tolerant
restore. `test/vault.test.js` asserts AES-256-GCM ciphertext-only persistence and fail-closed
tamper detection. `test/magpie-compat.test.js` evaluates `index.js` in a bare `vm` context to prove
moejs compatibility.

## Performance measurement

Measured on the reference machine with the bundled Node v24.21.0, `test/perf.test.js`:
`[perf] 50125-char synthetic doc: best 11.5 ms, median 12.3 ms, 2133 hits`
(after the review fixes; earlier runs were 10.2–13.5 ms) and a clean (PII-free) 50,050-char
document: **≈ 2.4–3.5 ms**. The first redact of a process pays JIT/regex-compilation cost
(≈ 40–60 ms); steady-state is the number that matters and is well inside the 50 ms budget. No nested
quantifiers are used. The only super-linear step was the candidate search inside a digit run in
`CARD`; the review measured 60 ms for 50 k digits and 380 ms for 300 k. Fixed: the detector first
rejects a start digit outside 3-6 and bounds very long runs to their ends, so 50 k digits now take
~7 ms, 300 k ~40 ms and 1 M ~110 ms (measured; `test/hardening.test.js` asserts the 300 k case).

## Interpretations / deviations from [the interface contract](../interface-contract.md)

1. **BLOB is masked as well as reported.** The interface contract says BLOB is "a block signal, not a mask
   target". `redact()` still replaces BLOB spans with a `{{BLOB_…}}` placeholder (defence in depth:
   invariant "no plaintext may appear in redact() output"), while `scan()`/`redact()` hits still
   carry `kind: "BLOB"` so gates can fail closed. Values of SECRET/BLOB are **not retained**, so
   `restore()` leaves their placeholders untouched (SECRET "never restore into a reply"; BLOB is raw
   bytes).
2. **PLZ Ort wording** — see `ADDRESS` row.
3. **BIC country scope** is DE + EU/EEA/CH/GB, not every ISO 3166 country (false-positive control).
4. **Additive internal exports**: `sha256Hex`, `hmacSha256Hex` (for the `node:crypto` cross-check) and
   `NON_RESTORABLE`; the Redactor carries `_entries()`/`_hydrate()` used only by `vault.save/load`
   (the gate never sees values, so the vault must read them from the redactor). These are documented
   as not part of the frozen public surface.
5. **`vault.load(redactor?)`** takes an optional redactor to hydrate; `load()` with no argument still
   loads into memory so `vault.get(token)` works per contract.
6. **`stats()`** accumulates over both `scan()` and `redact()` calls; a caller that calls both for the
   same text counts `charsScanned` twice (byKind is a hit count, not duration).
7. **Additive detector extensions**: Bearer tokens, `github_pat_`, AWS `AKIA`, spaced/lowercase
   IBANs, US EIN shape under `Tax` context, base64-header ZIP smuggling. All are masking-only
   extensions in the privacy-safe direction and are covered by tests.
8. **Contract point unimplementable as written**: "Tests: `node --test test/`" is not supported by
   Node v24.21.0 for a directory argument; resolved with `test/index.js` as the directory entry
   point (command works as written, no contract change needed).
